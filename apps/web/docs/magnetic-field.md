# Crustal magnetic field layer

Open **Layers → Magnetic field · crustal strength**. The overlay works in 3D,
2D, Compare and the overview. Its legend reports nanoteslas (nT), a fixed
logarithmic color scale and an interpolated value at the view centre. Opacity
and evaluation height are remembered. Elevation and magnetic colors are
mutually exclusive so one legend describes the visible scientific overlay.

The magnetic tint defaults to 40% opacity over the surface photography in
3D, 2D and Compare. Its full 0–100% range is adjustable in 1% steps, with a
visible 65% reference mark and a warning that surface-detail visibility
decreases significantly beyond that tint. At 0% the tint is transparent;
at 100% it completely covers the underlying imagery. The chosen value is
remembered across reloads. This display blend changes neither field values
nor the legend's color scale.

The source is Langlais et al. (2019), *A New Model of the Crustal Magnetic Field
of Mars Using MGS and MAVEN*, JGR Planets 124, 1542–1569.

- Paper: https://doi.org/10.1029/2018JE005854
- Author-published coefficients: https://doi.org/10.5281/zenodo.3876714
- Dataset uses MGS MAG, MGS electron-reflectometer and MAVEN MAG observations.
- Degree 134; approximately 160 km resolving power at the reference surface.
- The default is field magnitude evaluated 150 km above the 3,393.5 km model
  reference sphere. The alternative is evaluation on that reference sphere.
  This is a static crustal-field model, not a live measurement or a prediction
  following local topography. Neither zoom nor the 0.5° output sampling improves
  the underlying model resolution.

## Reproducibility and verification

`tools/build-magnetic-model.py` uses `pyshtools==4.13.1` and NumPy. These are
preparation dependencies, not new website/server dependencies. Run the script
from the project directory to regenerate `public/magnetic/`.

The original coefficient digest is
`3cad9e268f0673be1702f1df504a4cbcb8dba4480c7b3f629921911488fe247b`,
matching the official SHTOOLS Mars dataset loader. The script uses the same
header skip, 3,393.5 km reference radius, nT units, Schmidt normalization and
Condon–Shortley phase convention. Full degree 134 is retained at both heights.

The grid is generated by SHTOOLS magnetic vector synthesis and stores |B| as
little-endian Float32, north to south, at 0.5° nodes. Longitude is east-positive,
starts at −180° and is periodic. Both poles are included. Separate point
synthesis checks 25 locations per height, including both longitude hemispheres
and near-polar points, against vector magnitudes. Exact poles use the analytic
Schmidt-harmonic limit (m=0 radial and m=1 horizontal terms), checked against
point synthesis at ±89.9999°. The library's coordinate-pole horizontal zeros
must not be treated as physical field zeros. Pole totals are independent of
longitude. The manifest retains checksums, parameters, ranges and check values.

The browser checks the packet SHA-256 and geometry before displaying it. Failure
leaves the model unavailable with a retry action; no substitute field is made.
The two complete hemisphere textures remain coherent across zoom levels. Color
limits are 0–2,000 nT at 150 km and 0–20,000 nT on the reference surface, using
`log(1 + B/10)`; they do not adapt to the visible region. Numeric values are sampled
from the verified scalar grid independently of opacity and map appearance.

Sources:

- https://github.com/SHTOOLS/SHTOOLS/blob/v4.13.1/pyshtools/datasets/Mars/__init__.py
- https://shtools.github.io/SHTOOLS/python-shmagcoeffs.html

Tests cover source digests and point-synthesis values, coordinate orientation,
longitude wrapping, poles, both heights, color mapping, corrupted packets, retry
and cache behavior, and exclusive overlay controls.

Prepared canvas imagery still uses an asynchronous `requestImage` result:
Cesium 1.145 calls `.then(...).catch(...)` on it directly. Returning a bare canvas
stops rendering with `a.then is not a function`; the provider regression checks
the then/catch contract on repeated reads of both hemispheres. The magnetic
legend uses the same altitude-HUD clearance as the elevation legend.
