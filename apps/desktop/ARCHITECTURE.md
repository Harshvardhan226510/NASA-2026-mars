# Desktop architecture

Electron serves the established frontend through an application-owned production HTTP server on a random loopback port. Vite runs only at build time. Cesium 1.145 scripts, widgets, workers, styles and notices are local. Python route and celestial calculations run in the private PyInstaller service; GGUF inference runs in the private pinned llama-server process. Neither end-user operation depends on a reference checkout or global developer runtime.

The renderer uses context isolation, Chromium sandboxing, no Node integration, disabled webviews, restricted navigation and fixed preload operations. IPC verifies the sender and main-frame origin. HTTP requires a random session token attached only to the exact app origin, and validates Host and Origin. Static/package paths resolve within their real roots, data is streamed with bounded ranges, and package assets cannot execute as app pages. Unknown APIs, foreign origins and unsupported methods are rejected.

Offline is the initial, persisted mode. Backend fetch/native HTTP guards and Electron session filters enforce it, track response bodies until completion and abort outgoing work when switched offline. The session uses direct connections rather than system proxies. No automatic updates, model downloads or remote executable code are allowed. Public HTTPS sources require explicit Online Mode; missing source data never trigger a mode switch. Local model inference stays available offline. OS-level packet/DNS testing is a separate acceptance task and is not replaced by these guards.

The production server reuses original raster/surface/elevation contracts. LocalMapProvider maps verified native asset IDs to manifest-listed original COG bytes, retains provenance, validates affine geometry/CRS/dimensions, and returns bounded ranges through existing decoders. Multiple active datasets precede matching remote records. Missing storage is excluded from coverage. Overview-only packages retain genuine coarse imagery during close zoom without claiming higher source resolution. Shared backend caches use a 64 MiB LRU/TTL pool.

Registry/settings writes are serialized and atomic. Corrupt settings default offline; unreadable map/model registries preserve backups and allow the coarse starter viewer to recover. Registrations refer to files in place. Unregistering never deletes the user's source files. Downloads retain verified-size partials and finalize only after complete transfer; registry admission requires hash verification.

ARES accepts only the configured aliases and bounded messages. Its loopback server has a random key, offline flag, no web UI, owned lifecycle, context/tokenizer checks, CPU threads and memory admission checks. Redirects are rejected. Only allowlisted map/virtual-mission actions with validated parameters execute. No shell/filesystem action is exposed. Evidence and current question are never silently truncated to fit; old turns can be removed. Model-generated text remains advisory.

Desktop browser speech recognition is disabled because no private local ASR engine is bundled. Speech output selects only voices marked localService and skips output when none exist. The older website/CLI Ollama/Python recipes remain developer references and are not the desktop production path.

Cesium 1.145's Knockout bindings and generated terrain workers require script-src 'self' blob: 'unsafe-eval'. Remote executable resources remain prohibited by the session policy and CSP. Removing these compatibility allowances requires a validated Cesium/widget refactor. This limitation is explicit, not a claim of an eval-free renderer.

Original coordinates, missing-value semantics, unexaggerated scientific terrain and three-profile routing are preserved. Dated surface spacecraft positions are explicitly historical offline. Atmospheric/environment/space-weather and orbiter API snapshots requiring an online service currently return unavailable offline, even where reference release files are present. Their observation/model times are never relabelled as current.
