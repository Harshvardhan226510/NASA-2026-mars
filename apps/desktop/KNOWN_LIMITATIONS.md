# Engineering build limitations

- The user-supplied original Q8 GGUF has passed real local inference and assistant checks. Its source/training provenance and domain accuracy remain partly unverified; see docs/ARES_MODEL_PROVENANCE.md. Weights are a separate user import. No Mars-domain accuracy, zero-hallucination or safety certification claim is made.
- Source/data redistribution rights need review: no standalone upstream licence was present. Preserve original mapping, model/mesh, NASA/JPL, Murray Lab, NAIF/SPICE and third-party notices. Public release is pending rights clearance.
- Starter imagery is globally coarse (about 5.2 km/pixel); MOLA is 4 pixels/degree. Real study-area fixtures are source overviews, not native HiRISE detail or obstacle clearance. Fine coverage must actually be installed or available online.
- Map-folder import/native COG activation and public Drive/HTTPS downloads work. General archive extraction, arbitrary raster conversion, private Drive OAuth, curated production package catalogue, dependency/version upgrades, repair and partial-file cleanup UI remain incomplete. The production map catalogue has no approved entries. Unregistering preserves files.
- Offline local science includes original static layers, analytical solar geometry, supported route calculations, dated surface positions and private SPICE moons. Live/modelled atmospheric, environment, space-weather and orbiter APIs currently report unavailable offline; the local developer API can query the included EMARS snapshot and user-submitted instrument readings.
- App/session/backend guards and observed request counts are verified. Whole-system disconnected, DNS/socket capture and adversarial process-level acceptance are still pending; zero observed external requests is not an OS isolation certificate.
- Offline English microphone input uses bundled whisper.cpp tiny.en with transcript review. Native synthesis/recognition and a controlled Windows app microphone test passed. Physical microphone/speaker accuracy and Pi latency remain untested. Optional OS-independent spoken replies use a separate Piper engine/English voice ZIP; download it through the private GitHub release and import it in ARES Voice. No GitHub token is embedded. See docs/ARES_OPTIONAL_VOICE.md.
- Windows build and application smoke checks do not substitute for a clean Windows VM installation, Start menu, upgrade/uninstall/data-persistence and recovery campaign. Artifacts are unsigned and use the default Electron icon.
- ARM64 CI packaging, normal installation and starter-globe rendering on the user-provided Pi have passed. Broader Pi graphics compatibility, thermal throttling, shared 8 GB memory, performance and model/map coexistence testing remain pending.
- Cesium needs local eval/blob-worker compatibility in CSP. Original frontend's large bundle and default rendering settings need further low-power profiling.
- No blanket feature-complete status is implied. See TEST_REPORT.md and docs/FEATURE_STATUS.md for tested scope.

## Map Manager customisation

Whole-Mars quality, regional resolution, rectangle/circle/lasso/coordinate selection, colour/grayscale preferences, storage estimates and progressive scheduling are implemented. Automated geometry, seam and appearance checks passed; complete map-download/recovery and physical-device performance acceptance remain pending. The curated prebuilt catalogue is empty. Direct downloads offer source-specific imagery, shaded relief and HRSC/MOLA elevation tiers. HiRISE downloads are limited to supported site mosaics. Every supported resolution remains selectable; a red Storage exceeded counter warns when the selection exceeds available storage, and download preflight prevents starting an oversized transfer. Source packages support up to 1,000,000 tiles each; larger archives require separate sections. Native COG fixtures are grayscale. Large global archives need a reviewed indexed/sharded format; cleanup/reconciliation and cross-package deduplication remain incomplete.

## Dead reckoning prototype

Starting location, Engage/Pause, calibrated motion/encoder/step input and ready Mars-position input, persistence/export and an independent estimated track are implemented. Eight automated behavior checks and a Windows app interaction passed. External processes can submit supported packets through the opt-in localhost API in the source checkout. Raw IMU fusion, direct hardware adapters, coordinate alignment, absolute correction and hardware accuracy await the prototype. No motion is inferred from a camera or planned route. See docs/DEAD_RECKONING.md.
